Generator

The families -C/-D/-E/-W, the scale options, and the instances they build

Without -d, zeno builds the instance with the generator of the 2016 solvers, from the options -n -t -p -C -D -E -W -r -j -k -l -m -x -y (command line). The construction is that of legacy::buildInstance (src/zeno/legacy_input.cpp), quirks included, so zeno and the 2016 zenoSolver see the same instance for the same options.

Generating functions

-C, -D, -E and -W each take a code:

Code Function \(f(k)\) Name in the suites
1 \(\ln k\) log
2 \(\sqrt k\) sqrt
3 (default) \(k\) linear, identity
4 \(2^k\) pow2
5 \(5\lfloor k/2 \rfloor + 0.1\,(k \bmod 2)\) staircase, the “(5/2)\(i\)” family

Any other code falls back to the identity, as in 2016. The argument \(k\) is truncated to an unsigned integer before \(f\) is applied, as the 2016 functions took unsigned.

Construction

For cities \(i = 1, \dots, n\), with \(r\) = -r, \((j, k)\) = -j -k, \((l, m)\) = -l -m and \((x, y)\) = -x -y (defaults \(r = 1\), \(j = l = x = 1\), \(k = m = y = 0\)):

  1. Costs on increasing arguments, durations on decreasing ones: \[c_i = x\,f_C(\lfloor j\,i + k \rfloor) + y, \qquad d_i = x\,f_D(\lfloor l\,(n+1-i) + m \rfloor) + y.\] With -E and -W (both needed; -D is then ignored), \(d_i\) uses \(f_E\) and the \(C_G\)-side \(\bar d_i = x\,f_W(\lfloor l\,(n+1-i) + m \rfloor) + y\).
  2. Every value is multiplied by \(r\) and truncated toward zero: \(v \leftarrow \operatorname{trunc}(r\,v)\). -r 100 keeps slowly growing functions such as \(\ln\) from collapsing onto a few integers.
  3. The swap. If \(d_1 > d_2\), durations and costs are exchanged and \(\bar d\) is reversed (model). For increasing functions on decreasing arguments \(d_1 > d_2\) holds unless truncation makes the first two values equal. So in practice:
Options Swap? Durations \(d_i\) \(C_G\) side \(\bar d_i\) Costs \(c_i\)
-C a -D b yes (usual) \(\operatorname{trunc}(r\,(x f_a(ji+k)+y))\) \(= d_i\) \(\operatorname{trunc}(r\,(x f_b(l(n+1-i)+m)+y))\)
-C a -D b no (tie) \(\operatorname{trunc}(r\,(x f_b(l(n+1-i)+m)+y))\) \(= d_i\) \(\operatorname{trunc}(r\,(x f_a(ji+k)+y))\)
-C a -E e -W w yes (usual) \(\operatorname{trunc}(r\,(x f_a(ji+k)+y))\) \(\operatorname{trunc}(r\,(x f_w(li+m)+y))\) \(\operatorname{trunc}(r\,(x f_e(l(n+1-i)+m)+y))\)
-C a -E e -W w no (tie) \(\operatorname{trunc}(r\,(x f_e(l(n+1-i)+m)+y))\) \(\operatorname{trunc}(r\,(x f_w(l(n+1-i)+m)+y))\) \(\operatorname{trunc}(r\,(x f_a(ji+k)+y))\)

(the floors inside \(f\) are left out for readability). After the usual swap, durations increase with \(i\) and costs decrease: faster cities cost more, which is what makes the front non-trivial.

Non-symmetric options that give a symmetric instance

After the swap, the \(C_I\)-side durations come from -C and the \(C_G\)-side ones from -W. When the two functions coincide the instance is symmetric, whatever -E says. -n 3 -E 1 -W 3 (with the default -C 3) is symmetric, and zeno solves it as such. Use a -W different from -C, for example -E 3 -W 2:

$ zeno generate -n 4 -t 3 -p 2 -E 3 -W 2 -r 10
10 20 30 40
10 14 17 20
40 30 20 10

Examples

These are the outputs of zeno generate (durations, then costs; 3 lines when non-symmetric):

Options Instance
-n 4 (defaults, linear) \(d = (1, 2, 3, 4)\), \(c = (4, 3, 2, 1)\)
-n 4 -C 2 -D 2 -r 10 \(d = (10, 14, 17, 20)\), \(c = (20, 17, 14, 10)\)
-n 10 -D 1 -r 100 \(d = (100, 200, \dots, 1000)\), \(c = (230, 219, 207, 194, 179, 160, 138, 109, 69, 0)\)
-n 10 -D 1 (tie: no swap) \(d = (2, 2, 2, 1, 1, 1, 1, 1, 0, 0)\), \(c = (1, 2, \dots, 10)\)
-n 4 -E 3 -W 2 -r 10 \(d = (10, 20, 30, 40)\), \(\bar d = (10, 14, 17, 20)\), \(c = (40, 30, 20, 10)\)

Zero values are allowed and do occur: \(\ln 1 = 0\), so the log family has a city of duration or cost 0.

The families in the suites

The families suite runs every family on \(n = 10\), \(t = 8\), \(p = 3\) (suites): linear (-C 3 -D 3), log (-C 1 -D 1 -r 100), sqrt (-C 2 -D 2 -r 100), pow2 (-C 4 -D 4), staircase (-C 5 -D 5 -r 10), and the mixed log-linear and sqrt-linear. The default family is the only one with a closed-form front (known fronts). The others need the general algorithm, and on them the 2016 greedy can miss points.

Every instance the generator builds without -E/-W is symmetric, and every PDDL problem zeno writes from it satisfies (A1), so its front is exact.
