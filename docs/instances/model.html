Model and data files

What an instance is, and the 2-line and 3-line data files

The model

A MultiZenoTravel instance (§1.1 of the note) has

  • two hubs, the initial city \(C_I\) and the goal city \(C_G\), and \(n\) central cities \(1, \dots, n\);
  • flights between a hub and a central city: \(C_I\)–\(i\) lasts \(d_i\), \(i\)–\(C_G\) lasts \(\bar d_i\), in both directions. There is no flight \(C_I\)–\(C_G\). Central-to-central flights may exist;
  • a landing cost \(c_i\) in central city \(i\) (landing in a hub is free);
  • \(p\) planes and \(t \ge p\) passengers, all in \(C_I\) at time 0. A plane carries at most one passenger, and boarding and debarking take no time.

A plan flies every passenger to \(C_G\) and ends every plane in \(C_G\). Its cost is the sum of its landing costs and its makespan the time the last plane reaches \(C_G\). The front is the set of Pareto-optimal (cost, makespan) pairs over all plans, which may wait anywhere, hand passengers over anywhere, and use central flights (§1.2). Every plan lands at least \(s = 2t - p\) times in central cities (Lemma 3.2).

What zeno stores is d, dbar, c, t and p; durations, costs and times are non-negative integers. The assumptions (§1.4) are

  • (S), symmetry: \(d_i = \bar d_i\) for every city. Every instance the generator builds without -E/-W is symmetric;
  • (A1), under (S): central flights are no faster than through a hub, \(d_{ij} \ge d_i + d_j\). Every PDDL problem zeno writes satisfies it (central flights last \(\max(d_i, \bar d_i) + \max(d_j, \bar d_j) + 100\));
  • (A1-NS), the non-symmetric version: \(d_{ij} \ge \min(d_i + d_j, \bar d_i + \bar d_j)\);
  • (AΔ), the triangle inequality on the flights that exist: \(\mathrm{dur}(a, b) \le \mathrm{dur}(a, x) + \mathrm{dur}(x, b)\).

The front zeno prints is exact for symmetric instances under (A1), and by the note’s Corollary 4.12 under (AΔ) as well. For non-symmetric ones it is exact wherever the certified bracket closes, under (A1-NS) when a bound needs it (command line).

Data files

-d FILE reads the durations and costs from a file instead of the generator. -n must still be given and must match the file. Two layouts:

2 lines, symmetric: durations, then costs.

6 10
40 20

This is tests/golden/data/lpt-counterexample.dat: \(d = (6, 10)\), \(c = (40, 20)\). With -n 2 -t 5 -p 2 it is the smallest instance on which the 2016 greedy misses a front point (§5).

3 lines, possibly non-symmetric: \(C_I\)-side durations \(d\), \(C_G\)-side durations \(\bar d\), costs.

3 19
3 11
5 1

This is the instance of Proposition 6.5 (zeno -n 2 -t 7 -p 4 -d prop65.dat), on which waiting is harmful. A 3-line file with equal first and second lines is symmetric.

Reading rules (src/zeno/legacy_input.cpp):

  • tokens are separated by whitespace, and every non-blank line must have exactly \(n\) of them; blank lines are skipped, so a trailing newline or blank line is harmless (the golden instance trailing-newline checks it);
  • each token is read as an integer (std::stoi): 3.7 reads as 3, and a token that does not start with a number is an error;
  • the file must have 2 or 3 non-blank lines;
  • every value is then multiplied by -r (default 1) and truncated toward zero, as for generated instances, and negative values are rejected.

A data file is read as written: the first line holds durations and the last line costs, in any order of the cities, and the order of the cities does not change the front. zeno generate writes an instance in this format (command line), so its output reads back as the same instance.

The 2016 solvers read a data file differently when its first duration exceeded its second: they exchanged the duration and cost lines, and reversed the \(C_G\)-side durations. To reproduce a 2016 result from such a file, write it with the lines in the order the 2016 solver used them (2016 and paper instances).
