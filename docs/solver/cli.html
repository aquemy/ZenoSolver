Command line

The four commands of zeno and every option

zeno [front] [instance options] [--threads N] [--levels MODE] [--plans] [--certificate FILE] [--stats]
zeno check CERTIFICATE
zeno pddl [instance options] [-O FILE] [--no-front]
zeno generate [instance options] [-O FILE]

The first argument selects the command; without one, zeno runs front. -h or --help anywhere prints the help below, which is the output of the current build (regenerated with the site). An unknown option is an error.

$ zeno --help
usage: zeno [front] [instance options] [solver options]
       zeno check CERTIFICATE
       zeno pddl [instance options] [-O FILE] [--no-front]
       zeno generate [instance options] [-O FILE]

front     Pareto front (cost, makespan) as "cost makespan" lines by
          increasing cost (the default command). Exact for symmetric
          instances whose central flights satisfy (A1) or the triangle
          inequality (AΔ) (Theorem 4.10, Corollary 4.12; in Lean,
          solveFront_isParetoFront_ATri): the default table satisfies (A1),
          --metric tables (AΔ). With a central-flight table,
          stderr says which holds, or warns that the front may not be exact
          (Example 4.13). For non-symmetric instances: achieved points
          (simulated plans) and, on stderr, which gaps a lower bound
          certifies
check     verify a front certificate (doc/certificate-format.md) and print
          the assumptions it relied on (S; A1|AD: central flights satisfy
          (A1) or (AΔ), as for the Lean checker, Cert.check_sound_A1 and
          Cert.check_sound_ATri; A1-NS)
pddl      write the instance as a PDDL problem for pddl/multi-zeno-travel.pddl,
          with its front as comments unless --no-front (default file
          zeno<n>n<t>t<p>pMulti.pddl)
generate  write the instance as a data file for -d (default: standard output)

Instance (the options of the 2016 zenoSolver, without its swap; see below):
  -n N        central cities (default 3)
  -t N        passengers (default 3)
  -p N        planes (default 2), 1 <= p <= t
  -d FILE     data file: durations then costs (2 lines), or C_I-side
              durations, C_G-side durations, costs (3 lines); then, optionally,
              a line "central" and n lines of n central-flight durations
              (symmetric, zero diagonal). Without it, central flights last
              max(d_i, dbar_i) + max(d_j, dbar_j) + 100, which satisfies (A1)
  -C K -D K   generator of costs / durations: 1 log, 2 sqrt, 3 identity (default),
              4 power of two, 5 staircase
  -E K -W K   non-symmetric durations: -E generates the C_I-side durations,
              -W the C_G-side ones
  -r R        multiply before truncating to integers (default 1)
  -j -k       cost generator scale / translation
  -l -m       duration generator scale / translation
  -x -y       output scale / translation of both generators
  -F          accepted for compatibility (the front is always printed)

Metric instances (every flight lasts the distance between its ends):
  --metric plane|sphere  random points, uniform in the square [0, 100]^2
                         (plane), or uniform on a sphere of radius 6371 km with
                         great-circle distances (sphere)
  --seed S               seed of the points and of --random-costs (default 1)
  --hubs same|apart      same (default): C_I and C_G are one point, so the
                         durations are symmetric (S); apart: two points, and the
                         instance is non-symmetric
  --coords FILE          the points instead of random ones: one "x,y" (plane)
                         or "lat,lon" in degrees (sphere) per line, optionally
                         after a label; the hub first (C_I, then C_G with
                         --hubs apart), then the n central cities
  --random-costs LO,HI   uniform random integer costs (default: -C -j -k -x -y,
                         not scaled by -r)
  -r R                   distances are multiplied by R (default 1) and
                         rounded, then every duration becomes its shortest
                         path over the flights, so the table satisfies the
                         triangle inequality (AΔ) exactly. With --hubs same
                         the front is exact (Theorem 4.10, Corollary 4.12)
  -d -D -E -W -l -m do not apply. `zeno generate` writes the table as the
  "central" block of the data file.

Each option means what it says, and data files are read as written. The 2016
solvers swapped durations and costs whenever the first duration exceeded the
second, which their generator always did: a 2016 or paper instance
"-C a -D b" is "-C b -D a" here, and "-C c -E a -W b" is "-C a -E c -W b".
Two exceptions. When truncation ties the first two durations, the 2016 code
did not swap, so its flags mean the same here (-n 10 -D 1 -r 1 starts with
d = (2, 2, ...); `zeno generate` on both forms shows which case applies).
And zeno scales both duration sides of -E/-W with -l/-m, so the -E/-W rule is
exact only if the 2016 instance had the same -j/-k as -l/-m (the defaults
do); otherwise write it as a data file.

Solver (front):
  --threads N          worker threads (default: all cores)
  --levels MODE        auto (default), sweep (bracket every level) or search
                       (bisect for the breakpoints; for wide level ranges)
  --plans              after the front, print a plan for every point (checked
                       by simulation): one line per plane, legs as
                       from->to[depart,arrive] with the passenger carried (pK)
  --certificate FILE   write a certificate of the front to FILE
  --stats              print solver statistics on stderr
  -h, --help           this help

Exit codes: 0 on success; 1 on an error (the message on stderr starts with zeno:); 2 when zeno check rejects a certificate.

Instance options

All four commands but check build an instance from the same options, and each means what its name says: -C the costs, -D the durations, -E and -W the two duration sides; data files are read as written. The generator page gives the formulas, and the model page the data file formats.

Option Default Meaning
-n N 3 Central cities.
-t N 3 Passengers.
-p N 2 Planes, \(1 \le p \le t\).
-d FILE — Data file: durations then costs (2 lines, symmetric), or CI-side durations, CG-side durations, costs (3 lines). Every line has \(n\) integers. Overrides the generator.
-C K 3 Cost generator: 1 log, 2 sqrt, 3 identity, 4 power of two, 5 staircase.
-D K 3 Duration generator, same codes.
-E K, -W K — Non-symmetric durations: -E generates the CI-side durations, -W the CG-side ones. Both are needed; -D is then ignored.
-r R 1 Multiply every value by \(R\) before truncating it to an integer.
-j, -k 1, 0 Scale and translation of the cost generator’s argument.
-l, -m 1, 0 Scale and translation of the duration generators’ argument.
-x, -y 1, 0 Scale and translation of the output of every generator.
-F — Accepted for compatibility and ignored: the front is always printed.

-n, -t, -p, -C, -D, -E, -W and -r take integers; -j, -k, -l, -m, -x and -y take decimal numbers.

front: the Pareto front

zeno -n 2 -t 3 -p 2
4 8
6 6
8 4

One cost makespan line per front point, by increasing cost (so by decreasing makespan). Costs and durations are integers, and so is every makespan.

Symmetric instances (durations to \(C_I\) and to \(C_G\) equal, every generated instance without -E/-W): the front is exact. A zeno instance has no central-to-central flights; the front is that of the model in which they exist but are no faster than through a hub, assumption (A1), as in every PDDL file zeno writes (Corollary 4.8 with Proposition 7.1). The note proves that the same front holds for central flights that are faster but obey the triangle inequality (AΔ) (Corollary 4.12, not yet in Lean); with central flights that violate both, it can differ (Example 4.13). When every gap of the front is closed by the relaxation \(L\), the same front holds for central flights of any duration; the certificate then lists only relaxed gaps.

Non-symmetric instances (-E/-W, or a 3-line data file with different lines): zeno computes a certified bracket (algorithm). Stdout lists the points achieved by simulated plans, and stderr reports which gaps between them a lower bound closes:

zeno -n 4 -t 3 -p 2 -E 3 -W 2 -r 10 > front.txt
non-symmetric instance: 12 achieved points; fastest makespan certified; 11 of 11 gaps certified; the front is exact, assuming A1-NS

When the fastest makespan is certified and every gap is closed, the printed points are the exact front, under the listed assumption (A1-NS) when a bound needs it. Otherwise the report says the front is a bracket and lists each open gap:

  open gap between makespans M1 and M2: a plan with makespan < M2 costs at least B (achieved: C; REASON)

where the reason is either “a cheaper balanced configuration exists, no schedule found within the gap” or “the exact balanced program gave up” (a limit of SolveOptions was reached, below).

Solver options

--threads N
Worker threads for the level evaluations. Default 0: all hardware threads.
--levels MODE
How the levels \(T\) (half makespans, in units of the gcd of the durations) are visited. sweep brackets every level between \(T_{\rm lo}\) and \(T_{\rm hi}\), then runs the exact DP on the open ones. search bisects for the breakpoints of \(E\), which evaluates \(O(r \log(T_{\rm hi} - T_{\rm lo}))\) levels for \(r\) breakpoints. auto (the default) sweeps when the range has at most \(2^{12}\) levels and searches beyond. Use search for wide level ranges, for example durations scaled by a large -r.
--plans
After the front, print a plan for every point, each checked by simulation (checkPlan). One block per point, from the cheapest, then one line per plane, legs as from->to[depart,arrive] with pK when passenger \(K\) is aboard. Locations are CI, c1…cn and CG. 
# cost 6, makespan 6
plane 1: CI->c2[0,1]p1 c2->CI[1,2] CI->c1[2,4]p2 c1->CG[4,6]p2
plane 2: CI->c1[0,2]p3 c1->CG[2,4]p3 CG->c2[4,5] c2->CG[5,6]p1

Here plane 1 drops passenger 1 in city 2 and returns empty, and plane 2 picks that passenger up on its way back to \(C_G\).

--certificate FILE
Write a certificate of the front to FILE (format): version 1 for symmetric instances, version 2 for non-symmetric ones. A non-symmetric front gets a certificate only when its bracket is exact; otherwise zeno stops with no certificate: the front is a bracket with open gaps. Implies building the plans.
--stats
Print solver statistics on stderr: 
levels 2..4 (x1, 3 levels), cities 2, max tree 2
settled: bracket 3, pairs 0, chains 0, monotone 0, exact 0
work: 5 states, 105 relaxations
seconds: table 4.084e-06, bracket 3.9708e-05, chains 0, exact 0, plans 6.6083e-05
  • levels: the range \([T_{\rm lo}, T_{\rm hi}]\) of scaled half makespans, the gcd the durations were divided by (x), and the number of levels in the range;
  • cities: cities left after the dominance reduction; max tree: \(\min(p, t-p+1)\), the largest useful link tree;
  • settled: how the value of each evaluated level was established. bracket when \(L = U\); pairs when \(U\) is exact (trees of at most 2 planes); chains when \(U_3\) settles it; monotone when \(E\) takes equal values at both ends of an interval; exact counts the link-forest DP evaluations;
  • work: DP cells written and candidate transitions examined, summed;
  • seconds: time in the one-plane table, the bracket, the chains bound, the exact DP and the plans.

check: verify a certificate

zeno -n 2 -t 5 -p 2 -d tests/golden/data/lpt-counterexample.dat --certificate lpt.cert
zeno check lpt.cert
certificate accepted, assuming S

zeno check reads a certificate of either version and verifies the four obligations of the format. On success it prints the assumptions the accepted obligations needed (S: symmetric durations; A1: central flights no faster than through a hub, needed by forest gaps; A1-NS for the version 2 kinds other than relaxed). On failure it prints one error: line per failed obligation, then certificate rejected, and exits with code 2.

zeno check reuses the solver library’s dynamic programs for the gap bounds, so it is a consistency check of the solver, not an independent proof. The Lean checker zeno-check is the independent one.

pddl: write a PDDL problem

zeno pddl -n 10 -t 8 -p 3            # writes zeno10n8t3pMulti.pddl
zeno pddl -n 10 -t 8 -p 3 -O p.pddl --no-front

Writes the instance as a PDDL 2.1 problem for the domain pddl/multi-zeno-travel.pddl (PDDL page). The default file name is zeno<n>n<t>t<p>pMulti.pddl; -O FILE sets it. For a symmetric instance the front is solved and appended as comments, unless --no-front. Non-symmetric problems are written without a front.

generate: write a data file

zeno generate -n 4 -t 3 -p 2 -C 2 -D 2 -r 10
20 17 14 10
10 14 17 20

Writes the instance that the options describe as a data file for -d: durations then costs for a symmetric instance, or CI-side durations, CG-side durations, costs otherwise. Without -O FILE it writes to standard output. -t and -p are validated but not written. Reading the output back with -d gives the same instance.

Limits of the non-symmetric bracket

The non-symmetric bracket stops some of its searches at limits set in zeno::SolveOptions (include/zeno/solve.hpp). The command line uses the defaults; the library can change them.

Field Default Limits
roleStates 2,000,000 States of the exact balanced role program, per level.
roleWork 50,000,000 Transitions of the exact balanced role program, per level.
refineSeconds 30 Time after which the refinement of open gaps stops; the remaining gaps stay open, with their lower bounds.
searchWork 20,000,000 Work of the exhaustive gap search (role configurations with exact schedules), per gap.

A gap left open by a limit is reported as such (the exact balanced program gave up). It is not an error: the printed points are still achieved by simulated plans, and the reported lower bounds are still proved.

Values and limits

  • Durations, costs and times are non-negative integers (std::int64_t). The instance is validated: \(n \ge 1\), \(1 \le p \le t\), every vector of length \(n\), every value non-negative.
  • The certificate reader refuses values above \(2^{36}\), \(n\), \(t\) or \(p\) above \(10^5\), and more than \(10^7\) legs, so no sum in the checker can overflow.
  • For sizes and running times, see the size guidance.
